Restaurant Ops Hub

One portal for every team and vendor, with an AI agent doing the follow-ups
Samiya Sehgal
URN: 2302662

1What is it?

A restaurant chain works with many teams (outlets, purchase, maintenance, HR, owner) and many vendors (vegetables, maida, packaging, gas, electricity, IT, hiring agencies). Today all of this lives in phone contacts and notebooks. Restaurant Ops Hub puts every team and every vendor in one portal. An AI agent watches stock, contacts vendors on WhatsApp, and turns attendance into salary automatically.

2The big picture

Users → Frontend → Backend → Database. Only the backend talks to the outside services.

3The four parts

Frontend: what users see

One website / phone app for all teams. Each team sees its own screens: chat with the agent, stock, approvals, vendors, payroll.

Next.js · hosted on Vercel

Backend: the brain

Checks who is logged in, runs the AI agent, follows the rules (like the ₹ order limit), sends WhatsApp messages and runs daily and monthly jobs.

Python FastAPI · hosted on Render

Database: the memory

Stores vendors, items and stock, sales, orders, messages, employees, attendance and salaries.

Supabase (Postgres)

Outside services: helpers

Claude (thinks and decides), WhatsApp (talks to vendors), POS (sales data), biometric machine (attendance).

Called only by the backend

4A closer look

Inside each layer: the screens, the backend's three jobs, and what the database stores.

5How the frontend and backend talk

WayWhat happensExample
1. Request & answerThe portal asks the backend over the internet (HTTPS) and gets an answer back in JSON. The login token proves who is asking.Open the stock page → "Maida: 18 kg, 4 days left"
2. Live chatThe agent's reply streams in word by word while it works."Checking stock… ordering 50 kg…"
3. Live updatesThe database pushes new items to the screen without a refresh.A new order needing approval pops up
4. Messages coming inWhatsApp and the biometric machine send data to the backend by themselves.Vendor replies "OK, 3 pm"
